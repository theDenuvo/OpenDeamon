# Skill-Finder — поиск существующего скилла вместо изобретения своего

Противодействие прямой наблюдаемой проблеме: ядро изобретало возможности,
которые уже есть (101 156 скиллов в Skills Hub). Референс-инцидент —
генерация изображений: ядро пошло в веб-API, имея локальный GPU и
официальный скилл `stable-diffusion`, и отдало 2-байтный «результат».

## Вызов

```bash
python A:/OpenDeamon/functions/skill-finder/skill_finder.py "generate images from text" [--limit N] [--json]
```

Только stdlib. Работает и из хука, и из ядра.

## Как это решает проблему масштабирования

Каталог скиллов в системном промпте стоит ~1.6k токенов на 59 скиллов
и линейно растёт (~21k на 1000). Этот инструмент **не добавляет контекста
вообще**: поиск идёт по локальному JSON-кэшу хаба
(`hermes-home/skills/.hub/index-cache/hermes-index.json`, 101 156 записей,
49.5 MB) внутри процесса — без сети, без вызова инструмента в окно контекста.

Встроенный `agent.coding_context: focus` НЕ решает задачу: он жмёт только
18 категорий из статического deny-list `_NON_CODING_SKILL_CATEGORIES`
в `agent/coding_context.py`. Хабовые и новые категории в список не входят,
поэтому на 1000 скиллов экономия составила 23% (21.9k → 17.0k токенов),
а не в разы. Проверено замером на синтетических каталогах.

## Приоритет

    локально установленное → Skills Hub → GitHub → веб → построить самому

Одно жёсткое исключение, ради которого инструмент и написан: если задача
креативного класса (LOCAL_BEATS_WEB: image/video/tts/ocr/diffusion/...) и на
машине есть GPU — локально выигрывает у любого веб-сервиса. Инструмент печатает
`!! PREFER LOCAL` с именем GPU и объёмом VRAM. Именно это правило нарушило
ядро в инциденте с картинками.

## Что НЕ делает

Не роутер. Не выбирает за ядро — возвращает кандидатов и отдаёт решение
модели. Ограничивать пути решения нельзя: это и есть интеллект ядра.

## Грабли, найденные вживую (не теория)

- Хабовые записи неоднородны: `clawhub` кладёт в поле `name` цитатированное
  многострочное описание, а чистый slug — в `identifier`. Имя берётся из
  `identifier`, если `name` выглядит как проза (>48 символов, кавычки, >7 слов).
- Без нормализации окончаний (`images`→`image`) и разбиения дефисов
  (`text-to-image`) официальный `stable-diffusion` для запроса «generate images
  from text» набирал **score 0.0 и отбрасывался** — инструмент проваливался
  ровно на задаче, ради которой написан. Починка: `_norm` + `_tokens` и для
  имени тоже, а не только для описания.
- Стоп-слова вырезали слишком много (`from` оставался мусорным токеном).
- Порог «нужен хотя бы один хит в имени» был слишком строгим и ронял скиллы,
  чьё имя отличается, но описание точно совпадает с задачей.

## Проверка

```
python .../skill_finder.py "generate images from text"   # PREFER LOCAL + hub-кандидаты
python .../skill_finder.py "send email from inbox"        # email-inbox-triage, himalaya первыми
```

Обе проверки дают осмысленный ранжированный результат; посторонние скиллы
(`document-to-action-items`) в выдачу не попадают.
