# imggen — локальная генерация изображений на своём GPU

Железо: **NVIDIA GeForce RTX 5060 Ti, 16311 MiB VRAM**, 32 ГБ RAM.

## Основной путь: ComfyUI + Qwen-Image-2.1 (проверено)

```bash
py A:/OpenDeamon/functions/imggen/comfy_gen.py "промпт" \
    [--out PATH] [--steps N] [--size WxH] [--seed N] [--json]
```

Модель: **Qwen-Image-2.1 (Uncensored) fp8** — топ по скачиваниям среди
text-to-image на HuggingFace (сентябрь 2026). ComfyUI поддерживает
архитектуру `qwen_image21` нативно, через `UNETLoader`.

**Замеры:**
- 1024×1024, 20 шагов — **68.5 с** при уже поднятом сервере
- холодный цикл (подъём сервера + генерация) — **101.9 с**

Ручной запуск сервера (он же нужен, если автостарт не сработал):

```powershell
cd A:\ComfyUI
.venv\Scripts\python.exe -s main.py --listen 127.0.0.1 --port 8188 `
    --disable-auto-launch --lowvram --output-directory A:\OpenDeamon\generated
```

- `--lowvram` обязателен: fp8-unet и текст-энкодер 8.9 ГБ не уживаются на
  16 ГБ карте одновременно (указано в model card Qwen-Image-2.1).
- Модели лежат в `A:\ComfyUI\models\` как **hardlink** на файлы в HF-кэше
  (`A:\OpenDeamon\cache\hf`), поэтому место не расходуется дважды.

## Память, а не VRAM, — реальный ограничитель

Самая дорогая находка при внедрении ленивого старта.

ComfyUI грузит модель **не целиком в VRAM**: он «стейджит» её в RAM для
dynamic VRAM offloading — 8.9 ГБ текстового энкодера плюс 6.8 ГБ модели.
Когда лимит commit исчерпан, загрузчик падает с
`hostbuf_file_reader_read failed`, а клиент висит **900 секунд** и уходит в
таймаут без внятной причины.

| Состояние | Результат |
|---|---|
| commit 45.4 из 45.8 ГБ (занят браузером) | `hostbuf_file_reader_read failed`, таймаут 900 с |
| commit 13.8 ГБ, RAM свободно 22.7 ГБ | та же команда — 101.9 с, картинка |

**Проверяй память перед генерацией, а не VRAM.** VRAM в обоих случаях
выглядел одинаково (15.3 из 16.3 ГБ).

`comfy_gen.py` делает предикт: если доступно меньше ~18 ГБ commit, он
**отказывается за 0.2 с** с цифрами и подсказкой («закрой браузер»), а не
молча жжёт 15 минут. Отказ срабатывает и при уже поднятом сервере: стейджинг
происходит во время выполнения промпта, а не только на старте.

Замеры: два источника commit расходятся (Win32_GlobalMemoryStatusEx —
35.8 ГБ, Win32_OperatingSystem — 45.8 ГБ), поэтому порог проверяется по
**доступному** commit, а не по доле.

## Ленивый старт и гашение

`comfy_gen.py` сам поднимает ComfyUI, если :8188 закрыт, и взводит
отложенное гашение (`COMFY_IDLE_SHUTDOWN_S`, по умолчанию 900 с) отдельным
reaper-процессом — клиент короткоживущий, поэтому отсчёт должен пережить его.

Это не «приятно», а необходимо: постоянно живущий ComfyUI занимает ~17 ГБ
RAM, и следующий потребитель (локальное зрение `qwen3-vl:8b`) с ним на
16 ГБ карте не уживается.

Подъём сервера занимает **100–120 с** (плагины + probing бэкендов
comfy_kitchen), поэтому ожидание клиента — 4 минуты, не минута.

## Запасной путь: SD 1.5 (`imggen.py`) — ЗАБРАКОВАН

`runwayml/stable-diffusion-v1-5` — модель 2022 года. Владелец забраковал
результат словами «это не кот, это пластилин». На 768px/30 шагах SD 1.5
выдаёт терпимое фото, но потолок модели не поднять промптом, и она
примерно в 6 раз быстрее Qwen/FLUX.

Оставлен только как фоллбэк, если ComfyUI не поднялся:

```bash
py A:/OpenDeamon/functions/imggen/imggen.py "промпт" --steps 30 --size 768x768
```

## Облачный путь: Cloudflare Workers AI (`cloud_gen.py`)

Фоллбэк, когда локально недоступно или нужен другой бюджет. Требует
`CLOUDFLARE_API_TOKEN` + `CLOUDFLARE_ACCOUNT_ID` в
`A:/OpenDeamon/secrets/cloudflare.env` (в git не попадает).

```bash
py A:/OpenDeamon/functions/imggen/cloud_gen.py "промпт" --model auto
```

Free tier: 10 000 нейронов/день, без карты, **валится с ошибкой при
превышении, а не списывает деньги**. `auto` выбирает draft-тир
(klein-4b, ~104 нейрона) или финальный (FLUX.2 [dev], ~600) по остатку дня.
Подробности и честные ограничения — `RESEARCH_cloud_image_gen.md`.

## Проверка качества

Жёсткий порог (только «это реальная картинка, а не пустой холст»):
`bytes >= 5000`, `pixel_std >= 8`, стороны `>= 128`. Для ComfyUI-пути
проверку смотри в выводе `comfy_gen.py`.

**Жёсткий порог НЕ означает, что картинка хороша.** Ошибка 2026-09-30:
SD 1.5 на 8 шагах прошла порог идеально (385 KB, 9769 цветов), а
результат оказался пластилином. Порог ловит пустой/обрезанный файл и
ничего не говорит об эстетике.

Правило: **посмотри на изображение, прежде чем заявлять успех.**

## Грабли

**Диск A: кончился** (`No space left on device`) — модели Qwen заняли
45 ГБ из 221. Проверять свободное место **перед** скачиванием
многогигабайтных весов, не после.

**xet-бэкенд HF рвётся на файлах >10 ГБ**
(`Internal Writer Error: Background writer channel closed`). Лечится
`HF_HUB_DISABLE_XET=1` — уже прописано в `fetch_model.py`.

**Двойная перекодировка документации.** `Get-Content` в PowerShell 5.1 без
`-Encoding` читает UTF-8 как CP1251, а `Set-Content -Encoding UTF8` пишет
результат с BOM. Так файл превращается в нечитаемую кашу — это произошло
с этим же SKILL.md. Правь файлы инструментом или через Python, не
конвейером PowerShell. Тот же баг у TODO П.7 в `memories/MEMORY.md`.
