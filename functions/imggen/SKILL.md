# imggen — локальная генерация изображений на своём GPU

Железо машины: **NVIDIA GeForce RTX 5060 Ti, 16311 MiB VRAM**. Модель
`runwayml/stable-diffusion-v1-5` уже в локальном HF-кэше.

## Почему это существует

Референс-инцидент: на запрос фотографии ядро вызвало бесплатный веб-API,
когда локально стоял GPU с готовой моделью, и отдало файл в 2 байта,
который был засчитан как успех. Веб-сервисы для этого класса задач заметно
хуже по качеству и ещё и едят квоту. Теперь `skill_finder` печатает
`PREFER LOCAL` для креативных задач — это указатель сюда.

## Вызов

```bash
A:\OpenDeamon\venvs\img\Scripts\python.exe imggen.py "промпт" \
    [--out PATH] [--steps N] [--size WxH] [--seed N] [--hd] [--json]
```

Дефолты сознательно скромные: **768x768, 20 шагов** — это проверка
возможности, а не типография. `--hd` (1024px) — по явному запросу.
Замер: 512x512 / 8 шагов = **1.5 с**.

## Качество: SD 1.5 НЕ годен для фото (2026-09-30)

Пользователь забраковал результат SD 1.5 словами «это не кот, это пластилин».
Проверено на месте, разделив причины:

- **8 шагов / 512px** давали кашу; на **30 шагов / 768px** SD 1.5 выдаёт
  приемлемое фотореалистичное изображение (шерсть, боке, свет). То есть
  дефолты были сломаны И модель была слабой.
- **Но SD 1.5 — модель 2022 года.** Дальше потолок не поднять промптом.
  Нужна современная модель.

## Попытки поднять качество (все вживую, с фактами)

| Что | Итог |
|---|---|
| `black-forest-labs/FLUX.1-schnell` | **Гейт** — 401 без HF-токена |
| `Kijai/flux-fp8` | Веса есть, но это склад одиночных файлов: **нет `model_index.json`**, diffusers не грузит |
| `vantagewithai/Qwen-Image-2.1-ComfyUI-GGUF` | Тоже ComfyUI-формат, нет `model_index.json` |
| `unsloth/Qwen-Image-2.1-GGUF` + `Qwen/Qwen-Image-2.1` | **GGUF-pipeline не поддерживается diffusers.** Документация gguf.md прямым текстом: «Loading GGUF checkpoints via Pipelines is currently not supported». Нужен `from_single_file` на класс модели; на Qwen упирается в `Cannot copy out of meta tensor` (ветка GGUF-квантования не отлажена). Плюс BF16-компоненты Qwen — ~20 ГБ |
| `Freepik/flux.1-lite-8B` | ungated, полноценный diffusers-пайплайн, 8B — **подходит под 16 ГБ** |

Вывод по Qwen: на 16 ГБ VRAM полноценный Qwen-Image-2.1 не поднять без
ComfyUI-обвязки. Если качество станет критичным — ставить ComfyUI.

## Грабля, стоившая времени

**Диск A: кончился** (`No space left on device`) — модели Qwen заняли 45 ГБ
из 221. Проверять свободное место ПЕРЕД скачиванием многогигабайтных весов.
Удалено: Qwen-GGUF (24 ГБ) и Qwen BF16 (20 ГБ) — оба нерабочие.

Вторая ловушка того же рода: **xet-бэкенд рвётся на файлах >10 ГБ**
(`Internal Writer Error: Background writer channel closed`). Лечится
`HF_HUB_DISABLE_XET=1` — уже прописано в `fetch_model.py`.

## Проверка качества — измеримая, а не на глаз

Функция возвращает байты, размер, `pixel_std` и число цветов, и проверяет
**жёсткий порог**: `bytes >= 5000`, `pixel_std >= 8`, стороны `>= 128`.
Низкая дисперсия = однотонный холст, а не картинка.

**Жёсткий порог НЕ означает, что картинка хороша.** Это ошибка, совершённая
2026-09-30: SD 1.5 на 8 шагах прошла порог идеально (385 KB, 9769 цветов),
и я написал «качество подтверждено глазами» — картинка оказалась пластилином.
Порог ловит пустой/обрезанный файл и **ничего не говорит об эстетике**.

Поэтому вывод функции всегда печатает напоминание: посмотри на изображение,
прежде чем заявлять успех. Минимум для приемлемого результата:
`--steps 30 --size 768x768`.

Модели в порядке предпочтения: `runwayml/stable-diffusion-v1-5`,
затем `CompVis/stable-diffusion-v1-4`. Подойдёт любой совместимый
checkpoint diffusers.

## Стоимость и ограничения

- **Локально**, без сети, без ключа, без квоты OpenRouter.
- Все кэши на `A:` (`HF_HOME` прописан в коде). Окружение:
  `A:\OpenDeamon\venvs\img`.
- VRAM: SD 1.5 на 16 GB занимается с большим запасом; можно поднимать
  разрешение и брать более тяжёлые модели (SDXL/Flux), если понадобится.
- Время генерации линейно по шагам: 8 шагов ≈ 1.5 с, 20 шагов ≈ 4 c.
