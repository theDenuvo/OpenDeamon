# quota-watch — механическая защита кошелька

Хук `pre_tool_call`, который держит расход OpenRouter на нуле **механически**,
а не честным словом. Раньше лимит `$1` держался только на договорённости —
это не защита.

## Что делает

Читает реальный кредит-эндпоинт и вмешивается:

| Состояние | Действие |
|---|---|
| расход ≥ 90% от `$1` | **STOP** — сначала про деньги, бакет завтра восстановится, а `$1` нет |
| free ≥ 950/1000 | **STOP** — перейти на opencode-free ладдер |
| free ≥ 800/1000 | **WARNING** (один раз) — переключиться на локальное/бесплатное заранее |
| эндпоинт недоступен | fail-open, пропускает, пишет причину в state |

Деньги проверяются **первыми**: бесплатный бакет завтра восстановится,
потраченный доллар — нет.

## Детали

- Ключ: `$OPENROUTER_API_KEY`, иначе `$HERMES_HOME/.openrouter_key`.
  Никогда не логируется.
- Кэш чтения — 300 с (`cache/quota-watch.json`), чтобы один тёрн не стоил
  четыре запроса к кредит-эндпоинту.
- Предупреждение защёлкивается по порогу, чтобы не спамить в каждом ходе.
- Fail-open по построению: сеть легла — работа не блокируется.

## Конфигурация

В `config.yaml`, вторым хуком с `matcher: "*"`:

```yaml
- matcher: "*"
  command: "py -u A:/OpenDeamon/functions/quota-watch/quota_watch.py"
  timeout: 20
```

## Тест

```bash
py A:/OpenDeamon/functions/quota-watch/test_quota_watch.py
```

7 порогов с замоканными данными + проверка fail-open. Зелёный = решения
принимаются верно, включая приоритет денег над бакетом.
