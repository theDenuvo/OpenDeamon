## P0 — сломанное enforcement и зависший процесс

### 1. `quota-watch` не срабатывает: `matcher: "*"` — невалидный regex

**Ошибка.** В `hermes-home/config.yaml:78` для quota-watch указан
`matcher: "*"`. Hermes компилирует matcher как regex
(`shell_hooks.py:110`); `"*"` не компилируется, срабатывает fallback
`treating as literal equality` (`shell_hooks.py:113`). Литeral `"*"` не
равен ни одному имени инструмента → хук зарегистрирован и не вызывается
никогда. Подтверждение в `hermes-home/logs/errors.log`:

```
2026-09-30 15:03:26,774 WARNING agent.shell_hooks: shell hook matcher '*'
is invalid (nothing to repeat at position 0) — treating as literal equality
```

**Предложение.** Убрать поле `matcher` у quota-watch: в `_TOOL_EVENTS`
matcher опционален, а отсутствие поля по коду (`shell_hooks.py:118`)
означает «срабатывать на все инструменты» — это и нужно. Если поле
требуется форматом, заменить на валидный regex, покрывающий весь
алфавит (например `terminal|write_file|patch|edit|code_execution|execute_code|delegate_task|web_search|...`),
и обязательно перепроверить логом, что WARNING исчез. Пункт 4 (парсер) —
независимый баг, его тоже надо закрыть, иначе фикс matcher ничего не
даст.

### 2. `quota-watch` парсит устаревшую схему `/credits` → все поля `null`

**Ошибка.** `functions/quota-watch/quota_watch.py:100-114` ждёт от
`GET /api/v1/credits` вложенную структуру `data.usage.limit.daily_free_models`.
Живой ответ сейчас плоский:

```json
{"data":{"total_credits":10,"total_usage":0}}
```

Из него `usage = d.get("usage") or {}` → `{}`, поэтому `total_usage`,
`limit_usd`, `free_used`, `free_limit` все `None`. `verdict()`
(`quota_watch.py:140`) при `used is None` возвращает `allow`, то есть даже
после фикса matcher хук пропустит всё. Косвенное подтверждение:
`hermes-home/cache/quota-watch.json` содержит ровно `{"known": true,
"total_usage": null, ...}` — то есть схема не совпала при живом вызове.
Тесты этого не ловят: `test_quota_watch.py` мокает старую форму и зелёный.

Реальные лимиты лежат на другом эндпоинте (проверено живым вызовом):
`GET /api/v1/key` → `limit: 1`, `limit_reset: daily`,
`free_model_daily_requests: {used: 0, limit: 1000, remaining: 1000}`,
`usage_daily/weekly/monthly: 0`.

**Предложение.** Перевести `fetch_credits`/`measure` на `/api/v1/key`
(эндпоинт отдаёт и дневной бакет, и траты — оба порога нужны), удалить
ветку с `daily_free_models`. Тесты переписать на реальную форму ответа
(`/api/v1/key`), добавить кейс «плоская схема не должна молча давать
allow». Стоит зафиксировать в docstring, что оба эндпоинта наблюдались
живьём и схема меняется.

### 3. `comfy_gen.py` не забирает готовый результат: два бага, 15 минут впустую

**Ошибка.** Два независимых дефекта в `functions/imggen/comfy_gen.py`:

*a) Строка 193:* `q = f"/view?filename={images[0]}}&subfolder={'subfolder'}"`
— литерал `'subfolder'` вместо значения из ответа. Проверено живьём против
локального ComfyUI:

```
/view?filename=opendeamon_00001_.png&subfolder=           -> 200, 1 833 320 байт
/view?filename=opendeamon_00001_.png&subfolder=subfolder  -> 404
```

*b) Строка 178:* `hist = api(f"/history/{client_id}")` — ComfyUI ключирует
историю по `prompt_id`, а не по `client_id`. Клиент опрашивает
несуществующий ключ 900 секунд и падает с `TimeoutError`.

Симптом, наблюдаемый прямо сейчас: pid 25068 (`comfy_gen.py ... --size
1024x1024 --json`) висит с 18:02:51, CPU 0.5 с; очередь ComfyUI пуста
(`/queue` → `queue_running: []`); картинка `A:\OpenDeamon\generated\
opendeamon_00001_.png` (1.8 МБ) **уже записана диском в 18:05:03** — то
есть генерация отработала успешно, а клиент её не увидел. Тот же
`TimeoutError: no image after 900s` уже зафиксирован в `_setup_tmp/qc.json`.

**Предложение.** Сохранять `prompt_id` из ответа `POST /prompt` (поле
`prompt_id` в JSON-ответе) и опрашивать `/history/{prompt_id}`. Для
`subfolder` брать `img.get("subfolder", "")` и `img.get("type", "output")`
из той же записи истории. После правки — прогнать на 1024×1024 и
убедиться, что клиент завершился за ~2 мин (131 с по логу ComfyUI) и
`qc.json` содержит `"ok": true`. Параллельно имеет смысл добавить в
`generate()` проверку: если очередь пуста, а deadline близко — вернуть
диагностику, а не молчаливый TimeoutError.

## ФАЗА 1. Убрать то, что сейчас вредит

### 1.1 `quota-watch` — два независимых бага (диагностика П.1 и П.2)

**Баг A, matcher.** `hermes-home/config.yaml:78` — `matcher: "*"`.
Hermes компилирует matcher как regex (`agent/shell_hooks.py:110`), `"*"`
не компилируется и падает в literal-equality fallback
(`shell_hooks.py:113`), где сравнивается с именем инструмента как
строка и никогда не совпадает. Доказательство — `logs/errors.log`:
`2026-09-30 15:03:26,774 WARNING ... matcher '*' is invalid (nothing to
repeat at position 0) — treating as literal equality`.

Исправление: **удалить поле `matcher`** — при его отсутствии
`shell_hooks.py:118` означает «срабатывать на все инструменты», что и
нужно. Если формат требует поле — валидный regex по полному списку
инструментов.

Проверка: WARNING исчез из `errors.log`, а в
`hermes-home/cache/quota-watch.json` значения перестали быть `null`.

**Баг B, устаревшая схема.** `functions/quota-watch/quota_watch.py:100-114`
ждёт `data.usage.limit.daily_free_models`. Живой ответ плоский:
`{"data":{"total_credits":10,"total_usage":0}}`. Отсюда `usage = {}`,
все поля `None`, а `verdict()` (`:140`) при `used is None` возвращает
`allow`. Кэш это подтверждает: `total_usage: null`. Тесты зелёные,
потому что мокают старую форму.

Исправление: перевести на `GET /api/v1/key`, где лежат обе величины —

| Тест | Результат |
|---|---|
| тривиальный запрос | 200 за 1.36 с |

подтвердить без заголовков нельзя.

## ФАЗА 5. Управление UI — cua-driver, режим AX

### 5.1 Что выяснено (ломает ожидания, не обсуждается)

**Стриминга экрана не существует.** Ни в `tools/computer_use/`, ни в
cua-driver: ни live-view, ни MJPEG, ни VNC, ни параметра
fps/interval/continuous. Пакет даже не вызывает `resources/list` — только
20 инструментов по MCP через stdio. VNC live view, который можно было
видеть, принадлежит **браузерному** тулсету (Camofox/noVNC,
`tools/browser_camofox.py:113-152`) — другое подмножество, и браузер
задачей не является.

**Мультимонитор не поддержан:** `cua_backend_capture.py:34-37` —
«cua-driver captures one window at a time and exposes no
whole-virtual-desktop or per-monitor capture». Параметра
`display_index` не существует. На этой машине один монитор, так что не
блокер, но знать.

**Что реально даёт визуальную обратную связь:** cua-driver рисует на
настоящем рабочем столе полупрозрачный курсор агента, ездящий к каждой
точке клика; реальный курсор не двигается. На Windows включено по
умолчанию (`cua_backend.py:46-66`; на macOS выключено — рисует полный
перерисовкой и вешает ядро). Косметика: клики, ввод и скриншоты работают
без неё. Сессии различаются именем `hermes-<12 hex>`, так что
параллельные субагенты не путаются.

### 5.2 Главное: UI-контроль работает с текстовой моделью

`computer_use` **не требует зрения** от основной модели.
`tools/computer_use/vision_routing.py:58-74` фейлится **в сторону
aux-зрения**: скриншот у модели, которая его не читает, это жёсткий
400/404, а aux-маршрутизация стоит одного лишнего вызова и даёт пригодное
описание. Текущий `config.yaml:13-22` это уже объявляет.

| Действие | Нужно зрение |
|---|---|
| `list_windows`, `focus_app`, `wait` | нет |
| **`capture(mode="ax")` — дерево доступности, ноль пикселей** | нет |
| все действия по `element: N` | нет |
| клавиатура | нет |
| чтение нарисованного (canvas, видео, скроллбары) | да |

**Страховка:** если vision-модель вернёт 404,
`agent/message_sanitization.py` срезает image-parts и повторяет запрос
текстом, сохраняя роли и парность `tool_call_id`. Отказоустойчивость —
деградация, а не падение. Судя по 1.2, `dreamvision` в ZDR тоже 404-ит —
опора именно на AX-режим.

### 5.3 Установка

```
hermes computer-use install
```

Ставит `install.ps1` из `trycua/cua`
(`hermes_cli/tools_config_cua.py:644-649`), пакет в
`%USERPROFILE%\.cua-driver`, джункшн в
`%LOCALAPPDATA%\Programs\Cua\cua-driver\bin`. Контракт-гейт требует
semver ≥ 0.20.0 и вербы `mcp`/`serve`/`stop`
(`cua_backend_driver.py:154-192`). Планировщик `cua-driver-serve` для
обычной работы **не нужен** (только для SSH — Session 0 без рабочего
стола); его отсутствие деградирует, но не ломает установку
(`:305-312`).

**Блокеры Windows, знать заранее:**
- **SmartScreen.** При первом запуске `cua-driver-uia.exe` (UIAccess-воркер)
  выскочит предупреждение — разрешить.
- **UIPI — главный.** Процесс средней целостности не может ни читать
  UIA-дерево, ни вводить мышь в окно, запущенное от администратора.
  Симптомы обманчивы: `capture` вернёт 0 элементов, `click` отрапортует
  успех и ничего не сделает. Клавиатура проходит частично (Tab/Enter).
  Лечится запуском агента из повышенного терминала. **Проверить на
  первой же задаче и зафиксировать в SOUL как известный факт.**
- Не переустанавливать поверх `C:\Program Files\WindowsApps` —
  `CreateProcess` WinError 5. Штатный установщик кладёт в профиль, риска
  нет, но знать.
- `hermes update` на Windows намеренно **не** ставит cua-driver
  автоматически (нужен UAC).

### 5.4 Включение и режим

`computer_use` сидит в defer-листе `tool_search`
(`config_defaults.py:1979-1986`) — модель найдёт его через `tool_search`,
а не увидит сразу. `CODING_TOOLSET` его **выкидывает** (`toolsets.py:70`),
так что в кодинг-позе инструмента не будет. Для UI-задач ядро должно
переключать позу (`agent.coding_context`) — зафиксировать в SOUL.

Рабочий режим — **`mode="ax"`** (дерево доступности, без пикселей).
Режим `som`/`vision` включать только там, где UIA слеп.

Проверка: `hermes computer-use doctor` → `ok`; `list_windows` возвращает
окна; `capture(mode="ax")` отдаёт дерево без картинки; клик по элементу
из этого дерева работает.
